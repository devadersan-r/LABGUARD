3. Harden key management
Review labguard/key_manager.py and every function that loads, resolves, generates, saves, or exports keys.
Required changes
	•	Use a cryptographically secure random generator to create 32-byte keys.
	•	Validate key length, key encoding, key ID, and key-store structure.
	•	Validate that the configured key ID matches the key ID stored in its corresponding record.
	•	Validate the declared algorithm and reject unsupported algorithms.

	•	Preserve restrictive file permissions, including owner-only permissions where supported.
	•	Use atomic file writes when updating key stores or generated configuration files, and avoid leaving partially written files.
	•	Do not silently fall back to a new empty key store if an existing store is invalid.
	•	Do not log key bytes or key encodings.
Remove unsafe generic key fallback
The current generic environment variable LABGUARD_SECRET_KEY can allow the same secret to be accepted for arbitrary requested key IDs.
Remove this unsafe fallback from normal verification and key resolution.
Use explicit, key-ID-specific configuration, such as LABGUARD_KEY_<KEY_ID>, or a validated key store that maps each key ID to its own key.
A request for an unknown key ID must fail closed. It must never authenticate using an unrelated key merely because a generic environment variable is present.
Update has_key(), get_key(), firmware header generation, documentation, and all dependent tests to follow the same rule.
